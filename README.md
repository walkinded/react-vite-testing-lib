# React + Redux Toolkit: Testing Playground

Добро пожаловать в пет-проект, созданный для глубокого изучения и отработки навыков написания **Unit** и **UI (интеграционных)** тестов на современном фронтенд-стеке.

Проект представляет собой небольшое SPA-приложение с маршрутизацией и стейт-менеджером, где основной упор сделан не на сложный дизайн, а на качественное покрытие кода тестами.

## Стек технологий

**Основной стек:**

- ⚡️ [Vite](https://vitejs.dev/) — сборщик и dev-сервер
- ⚛️ [React](https://react.dev/) — UI-библиотека
- 🔷 [TypeScript](https://www.typescriptlang.org/) — типизация
- 🧰 [Redux Toolkit](https://redux-toolkit.js.org/) — управление состоянием
- 🧭 [React Router DOM](https://reactrouter.com/) — маршрутизация

**Инструменты тестирования:**

- 🟢 [Vitest](https://vitest.dev/) — сверхбыстрый тест-раннер (альтернатива Jest)
- 🐙 [React Testing Library](https://testing-library.com/docs/react-testing-library/intro/) — тестирование UI
- 🖱 [@testing-library/user-event](https://testing-library.com/docs/user-event/intro) — эмуляция реального поведения пользователя
- 🃏 [@testing-library/jest-dom](https://github.com/testing-library/jest-dom) — дополнительные DOM-матчеры (`toBeInTheDocument` и др.)

## Что и как тестируется?

В проекте реализованы и отработаны следующие подходы к тестированию:

### 1. Unit-тесты чистой логики (Redux)

- **Редьюсеры** (`counterReducer.test.ts`): проверка `initialState`, обработка экшенов (`increment`, `decrement`, `reset`), проверка иммутабельности.
- **Селекторы** (`getCounterValue.test.ts`): проверка корректного извлечения данных из стейта.

### 2. UI и интеграционные тесты компонентов

- Проверка начального рендера с использованием **`preloadedState`** (передача нужного состояния в store перед рендером).
- Симуляция кликов по кнопкам и проверка того, как обновляется интерфейс.
- **Тестирование с реальным store:** использование кастомной фабрики `setupStore` для создания изолированного хранилища на каждый тест (без утечки стейта между тестами).
- **Тестирование вызовов dispatch:** использование `vi.spyOn(store, 'dispatch')` для проверки того, что клик по кнопке отправляет правильный экшен, при этом UI продолжает работать естественным образом.
- **Изоляция окружения:** отработка мокирования `react-redux` (через `vi.mock`), когда компонент тестируется отдельно от реального store.

## 📁 Структура проекта

```text
src/
├── components/       # Переиспользуемые компоненты (Counter, NavBar) + их тесты
├── pages/            # Страницы приложения (Main, Users, About, Error)
├── router/           # Конфигурация маршрутизации (AppRouter)
├── store/            # Redux-хранилище
│   ├── reducers/     # Слайсы (counterReducer)
│   └── selectors/    # Селекторы + их тесты
├── users/            # Логика работы с пользователями + тесты
├── App.tsx           # Корневой компонент
└── vitest.setup.ts   # Глобальная настройка тестового окружения
```
